范围为已批准的六项改动；撤销上一段计时和长期任务结构调整已排除。

| 项目 | 实现与核查结果 |
| --- | --- |
| 完成执行片段 | 提交时保存完整秒级北京时间、片段引用与有效时长快照；重复打卡保存新增片段及用户日累计，避免每次复制重复累计。原始片段保留；合计以区间并集计算。 |
| 预计及超时 | 一个细条；预计内按有效预计时长显示，超时转红色时钟刻度，15分钟一格、60分钟一段。刻度重置时保留小时数与超时字样。暂停冻结并淡化；无预计和超时均不声称完成百分比。 |
| 今日收支 | 正数求收入、负数求支出；以含时区的可靠入账`at`分04:00用户日。补卡行为日和利息`effectiveAt`独立显示，不改结息规则或账目。 |
| 复制范围 | 任务事实、流水记录、笔记各自比较；不以历史结余触发后续日报修订。选定日列实际入账流水，往日变动仅补受影响任务／流水。只生成预览不推进复制状态。 |
| 底部任务重选 | 仅底部任务按钮在当前已为任务页时重置日期、子页及滚动；其他页面第一次点击恢复原上下文。程序导航和打开的弹窗不重置。 |
| 三栏进度 | 与复制文字共享投影，任务按逻辑引用去重，父子不重复计数；采用当天习惯安排目标。监督和无目标选做不计完成分母；空栏不显示100%。奖励资格继续调用原业务规则。 |

## 已核查的回归与边界

- 多次开始／暂停、结束后重开；暂停空隙不算有效时长，不把任务间隙称作休息。重合原片段仍可查，合计去重。
- 重复打卡25分钟后再18分钟，第二次新增18分钟、累计43分钟；跨04:00按目标日裁剪。快照生成后改名称或预计不改历史快照。
- 提交时重算未改写的默认完成说明；用户自定义内容保留，完整复制按需补足独立快照。
- 超时12分钟、恰好一个小时、下一秒换段、预计内刻度、暂停冻结；普通及长数字、深色主题和窄屏高度自适应。
- 实际入账、补记行为日、经济生效日分别核对；04:00前后各自计入正确用户日，退款及反向流水依据实际正负值分类。
- 修改一笔历史流水只带出该笔修订；任务状态和笔记真实补记仍保留。旧版文本基线升级不因余额漂移整批复制；同日重复复制继续携带待确认修订，下个用户日使用上次成功基线。
- 新基线保存后重新载入，切回旧日复制保留未来已知基线；损坏结构进入原有记录保护流程。重复制上次内容使用已保存的确切文本。
- 五种CSS窗口：320×640、390×844、550×350、770×490、1280×800。新增浏览器检查纳入GitHub验证工作流。

## 数据与发布边界

可选新增的是完成事件中的时段快照及复制基线。存储名与数据v1保持；不迁移原会话、不重写旧账、不追溯修改利率／奖励／长期任务规则。旧版代码忽略新增字段。只有原正常完成操作会停止运行会话并写入完成与积分。

缺少可靠入账时间的旧流水仍保留在总积分和完整导出，今日统计明确说明排除条数。升级前没有逐笔复制基线的历史财务差异无法准确重建，首次成功复制建立当前基线，不自动输出全部旧流水。旧完成事件没有详细快照时明确标注，不伪造时段。

本轮验证使用合成数据和桌面Chromium，不能替代小米14／安卓Edge的输入法、锁屏后台及VPN下载实测。发布需完成资源哈希、脚本、Node及浏览器检查，通过main验证后才将同一提交快进到gh-pages；保留上一版本代码与更新前数据快照。
