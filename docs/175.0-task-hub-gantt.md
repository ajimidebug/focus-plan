# 175.0.0 · 三栏习惯与双向长期甘特图

## 用户可感知变化

- 任务主界面继续保留三栏及长期项目甘特图。安排到某一栏的积分习惯重新在该栏展示；未安排习惯仍归积分页面。
- 习惯“每日目标”和“奖励次数上限”独立。目标达成后变绿、进度统计一次；若奖励上限高于每日目标，习惯仍在三栏正常位置，允许继续记录。积分继续由原有经济规则核定。
- 正常待办、真正延期到当前日期的活动待办、已完成与改期历史分开。历史改期记录默认折叠；原日期占位不再和当前任务混排。
- 纠正“提前改期”被历史状态描述为“补记”的误判。补记仍按原事件和退款机制处理。
- 长期项目甘特图支持现有项目类别筛选、分组折叠、超过 8 项默认显示 5 项、月／半年／两年／全部视图和时间导航。
- 甘特图内可创建每日推进长期项目；可经项目编辑器修改名称等字段，并通过快捷编辑更新类别、日期、前置项目及项目达成标记。
- 桌面端时间条可拖动整体或两端改变日期，松开后出现确认预览；触摸设备使用表单编辑。依赖边在同屏且均具有可见时间条时显示，跨类别依赖在项目文字中保留。
- 项目达成独立于每日打卡。依赖关系只做顺序提醒，不自动调整用户的任务、计时或积分。

## 数据与安全

- 继续使用 memoProjects、memoTaskGroups、memoHabitPlans 与 memoGanttDependencies；仅新增可选 memoGanttCompletedAt 字段，用户数据版本维持 v1。
- 模块导出包含长期项目类别名称与依赖引用；导入先创建项目、再重映射新 ID，校验依赖。不能确认前置项目时拒绝导入并报告缺失引用。
- 不创建与现有任务重复的甘特图数据源，不自动修改历史完成、时间片、积分流水；全量恢复仍使用原设置与备份入口。
- 旧数据或缺少类别的项目进入“未分类”。历史和折叠状态属于视图表现，不改变计分归属。

## 测试重点

1. 每日目标 1、奖励上限 99 的习惯在首次打卡后仍可见，进度只计算一次；撤销后状态正确。
2. 单日安排、每日固定安排、监督类型、选做类型均按日期与目标显示。
3. 改期、顺延、补记、撤销、跨日和重复复习保留原有效任务数量与账本。
4. 甘特图新建／修改／筛选／折叠、跨类别前置关系、日期冲突提示和循环依赖拒绝。
5. 模块导入导出中的新旧项目 ID 映射、缺失前置项目和重复导入。
6. 390px 移动端三栏和甘特图内部横向滚动，以及桌面拖动操作。
7. 全量构建、类型检查、存储／Node 回归和浏览器矩阵。

## 边界

- 甘特图的时间条填充代表已经经过的日历比例，不代表真实工程完成率。执行次数单独统计。
- 项目依赖不自动锁定后续任务，也不自动调整计划；改变日期需要用户主动保存。
- 原有完整数据备份与旧版本回退点需在 Pages 发布前保存并核验。
