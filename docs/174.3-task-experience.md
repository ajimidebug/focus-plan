# 174.3.0 · 任务权重、悬赏分级与计时交互

基线：已上线的 174.2.0（main `0b73df1038da25b9bfb7a928cacc25e64756ac8d`）。本版保持 173.9.1 视觉恢复及 174.2 复习、计时状态逻辑，不修改账本或原计时数据结构。

## 实施范围

1. **必做排序**：新字段 `priorityWeight`（1～5），未设置及非法值只在显示中按 3 处理；旧任务相对顺序不变。编辑必做时可调整权重，保存时要求有效整数。任务按未完成优先、权重降序、原相对顺序的稳定规则展示；理想和拓展继续按积分排序。颜色只影响任务左侧竖条，最高权重使用深红。
2. **悬赏**：11～30 分显示普通悬赏底纹，31 分及以上采用较明显的双层底纹，10 分及以下不显示。继续使用原积分、原规则和同一已存在的 `memoOrganize` 判定函数；不创建新奖励流水。概览、详细卡片及打卡安排行为一致。
3. **进度条**：保留四段 `延期完成 → 当日完成 → 普通未完成 → 延期未完成`，仅优化 6px 最小轨道高度；没有更改四段计数、原历史义务或颜色语义。
4. **悬浮计时**：暂停／继续为主要按钮；结束计时保留确认，任务与完成入口在展开时清晰可见，折叠时仅保留计时与展开，避免遮挡任务及时间轴点击。亮色进度条至少 7～8px；累计超过 1 小时后展开显示当前累计与暂停不计时说明，保留计划截止刻度与超时逻辑。
5. **随手记**：首次点击内容正文时不再强制跳到末尾；点击最后一行以下的空白区域时仍自动跳到末尾。选区、中文输入法组合、撤销与保存规则保持原样。

## 数据和回退

数据仍为 `focusPlanData.v1`；新增的 `priorityWeight` 为可选任务字段。旧备份缺失该字段时自动按 3 读取，不重新计分、不修改既有历史，不自动批量写回旧任务。历史任务只有明确保存后才会新增该字段。正式发布前已单独留存 174.2.0 的 `main` 和 `gh-pages` 回退分支；用户浏览器中的本地数据仍须自行下载完整备份。

## 验证门禁

`npm run check`、`npm run build`、`npm run typecheck`、`npm test` 与 GitHub Actions 全套 Playwright 浏览器脚本均须通过。新增浏览器断言检查：权重排序/保存、旧字段回退、11/31 悬赏边界、四段顺序及悬浮窗口高度/快捷按钮。实际 Android Edge 中文输入法、触摸、软键盘和后台计时需要真实设备进一步验收，不能用 Chromium 替代。

合并到 `main` 后 CI 自动暂存构建产物到 `release/174.3.0-built`；验证来源提交与站点资源清单后再将该候选合并至 `gh-pages`。源码和线上发布分别报告；构建成功本身不等于完成部署。
