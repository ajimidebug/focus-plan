# 业务与数据约束

1. 程序版本与业务数据版本分开。现有数据库名称、主存储键和 `version:1` 保持；新增字段必须兼容旧记录，未知模块版本停止写入。不能把读取失败当作新用户。
2. 用户日沿用北京时间 04:00 分界。自然日期轴与用户日统计分别处理；不把甘特图显示位置当作实际完成或计时归属。
3. 任务当前状态、历史完成实例、计时片段和积分事件分别保留。修改排序、筛选、折叠和显示方式不能重新结算积分或删除历史。
4. 完成、撤销、复习、延期、跨日计时涉及关联模块时，检查重复记账、重复生成、历史标题和时间归属。当前任务编辑不能无条件覆盖历史记录。
5. 175.7 起主数据先经 IndexedDB 读写事务校验已加载的修订号和提交标识，再写入；localStorage 作为同步镜像。其他页面写入后，旧页面停止写入并保留待保存内容，提示先导出。单页连续保存顺序提交各自快照。
6. localStorage 满而 IndexedDB 可写时允许保存并提示镜像不可用。IndexedDB 无法确认时，停止保存、保留内存内容并提示备份；不进行可能覆盖未知新记录的 localStorage 单独写入。恢复后可重试保存；重试保存快照，不重放积分或计时操作。页面关闭前必须关注保存状态，内存内容不能承诺跨刷新保留。保存尚未完成或失败时请求浏览器离页确认；浏览器需要用户交互才会显示，不能防止系统强制结束进程。
7. 保存成功仅在事务提交后报告。冲突和数据库异常不能被页面上的成功提示掩盖；完整备份与原始恢复导出各有用途，浏览器内快照不替代独立下载文件。旧版本页面不受新写入协议完全约束，升级前关闭其他旧标签页。
8. 用户导入的 Markdown/HTML 先清理后渲染，公式使用 KaTeX `trust:false`；仅最终公式结果保留必要内联样式。过滤显示结果，不改写原始卡片文本。所有新富文本入口都须检查同类风险。

这些约束覆盖本次触及的边界，不代表全项目已经形式化证明无缺陷。存储改动至少验证多页面竞争、两类存储故障、重试、连续保存和旧数据；渲染改动至少验证恶意输入、正常格式与公式；发布改动至少验证候选身份、失败阻断和资源一致性。
