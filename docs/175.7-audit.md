## 问题与处置

| 问题 | 影响 | 本次修改 |
|---|---|---|
| localStorage 失败时，多页仍可依次覆盖 IndexedDB | 旧页面保存可能丢失新记录 | 同一读写事务内比较修订/提交标识，冲突停止，覆盖真实事务与故障重试 |
| Markdown 原始 HTML 与可信公式命令直接进入页面 | 导入内容可能执行脚本或改变页面 | DOMPurify、两阶段清理、KaTeX 关闭可信命令，兼容界面同步保护 |
| 19 个浏览器任务重复准备环境 | 更新耗时和运行成本偏高 | 保留全部有效入口，三个官方容器任务，组内隔离进程、超时和日志归档 |
| 源码根目录存在过期的 release/worker 清单 | 直接测试源码产生误判，版本容易分叉 | 删除过期生成物，测试读取构建，版本从 package 统一生成 |
| 验证、构建、发布缺乏可复用候选边界 | 重建后的字节可能没有对应测试证据 | 一次构建，三组测试同一产物，以源 SHA 和整目录摘要校验 |
| 验证后生成候选分支，后续发布和回退缺少统一产物记录 | 后续发布需另行核验，历史产物难以复用 | 手动发布已验证 main 候选，检查版本复用、线上身份，成功后归档，按归档回退 |
| 上游历史部署说明仍醒目 | 可能误部署源码 | 当前维护入口、发布规范与业务规则，历史说明标注边界 |

## 取舍与剩余工作

- 保留现有 Vue/Quasar 和业务模块；本次不增加大规模架构迁移，不改变任务、计时、积分、复习的产品规则。
- 数据库不可写时牺牲临时的保存可用性，避免不能核验的覆盖。页面应提示下载备份，不能把“当前内存仍可读”写成“已保存”。
- 本地进行了完整构建、类型/源码检查、Node 回归与产物校验；额外覆盖多页冲突、真实卡片渲染、候选篡改、发布门禁、超时子进程和工作流结构。最终执行结果以本次交付及 CI 为准。
- 官方 Chromium 下载在本地环境失败，随后使用临时 Chromium 143.0.7499.0 与项目 Playwright 1.57.0 补跑，20 个有效浏览器入口全部通过，顺序运行约 205 秒；未弱化网页安全策略。额外核验了托管预览的笔记页、任务页启动与版本显示。此结果不等同于官方 CI 容器验证，CI 三组全通过前不具备正式发布证据。
- 最终本地验证：222 项 Node 测试、21 项账本检查通过；构建、类型检查、源码/YAML 检查和 72 项部署资源校验通过。测试入口统一加载本项目 Playwright，启动等待改用 `window.App` 防止全局尚未创建时报错。
- 依赖审计发现新加的 yaml 2.8.1 存在深层集合导致栈溢出的已公布中等级问题，已改为 2.9.1；最终 `npm audit` 对当前锁文件报告 0 项已知漏洞；该结果不等同于没有未知漏洞。
- 尚未推送、部署或更改 Pages / main 保护设置。新流程实际耗时、官方容器启动和 GitHub 权限仍待首次真实 CI/发布验证，不能承诺具体提速百分比。
- 此次修复了已复现的高优先级问题，不宣称整体项目无其他缺陷。后续按具体改动逐步抽取业务模块和补充边界测试，避免每次重复整仓审计。
