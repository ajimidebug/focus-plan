# 175.5.0 · 筛选视图、DDL、前两栏奖励与悬赏阈值

## 规则

- 甘特图可选月、半年、两年、全部或自定义范围；自定义起点为前天、昨天、今天（按用户当地自然日动态计算）或固定日期，终点为引用全局截止日期的 ID 或固定日期。`localStorage` 记住视图类型、日期规则、分组及折叠状态，不改动任务数据。引用截止日期被删除时提示重新选择；超长范围和颠倒日期保持安全显示并提示。
- DDL 置顶仅保证出现在紧凑展示中，不参与排序。取全部置顶项与最多凑齐 3 项的最近未过期未置顶项，最终按截止日期升序排列；超过 3 项置顶时全部显示。
- 悬赏门槛唯一来源为 `settings.memoBountyThreshold`（设置界面含边界），不再出现硬编码的 11 分。高级悬赏仍按 31 分或已配置阈值中较高者划分。
- 全部完成奖励仅按**必做、理想**两栏的目标判定；长期拓展不参与。安排在前两栏的正常习惯按所安排目标次数达标，监督类习惯不参与。新奖励保存目标引用快照（`scopeVersion:2`）并在任务或习惯撤销时核对，防止漏撤回或重复发放。
- 已发放旧版奖励不重写。无 `scopeVersion:2` 的奖励沿用旧的依赖校验；缺少依赖列表的旧奖励沿用旧三栏资格逻辑。
- 任务完成弹窗中的“加入队列”保留原有行为，避免尚未保存的字段丢失；入队成功后可继续操作。

## 验收

- DDL 远期置顶排列于较早的普通 DDL 右侧；紧凑展示默认为 3 项。
- 设置阈值 25 时，11/24 分不悬赏，25 分起悬赏。
- 自定义“前天 → 某 DDL”刷新后保留，跨自然日后起点移动，DDL 改期更新终点，删除后提示。
- 前两栏完成即允许领取全部奖励，即使第三栏未做完；普通习惯首次未达目标不能领取，达目标后可领取；撤销完成撤回所关联奖励。
- 175.1 浏览器回归中扩展以上行为；完整构建和历史账本测试由工作流执行。
